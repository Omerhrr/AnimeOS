# AnimeOS - AI-Native Animation Production Platform

> **DSH decides · Tools execute · Engine builds · State remembers**

AnimeOS is an AI-native production studio for animated and illustrated storytelling. It natively supports **donghua**, **anime**, **manhua/manhwa (comics)** and adjacent formats through one unified, stateful production pipeline - designed so an AI director (DSH) drives the studio through tools, not ad-hoc chat.

## Core thesis

```
DSH decides → tools execute → engine builds → render → DSH evaluates → revise → approve
```

Every step writes to a persistent production universe: projects, seasons, episodes, scenes, shots, characters (with episode-resolved states), relationships, assets, terminology and continuity events. Nothing lives only in a chat log.

**Stack:** Next.js 16 · TypeScript · Prisma/SQLite · TanStack Query · zustand · Tailwind · shadcn/ui · Three.js.

Per the replaceability principle, the render engine is a **pluggable driver** chain: headless Blender workers when a `blender` binary exists, the built-in MOTION engine (ffmpeg) otherwise, a wall-clock simulator as the last resort - the production state machine, queue and DSH evaluation loop are identical.

### Render engines

- **Headless Blender (auto-detected).** If a `blender` binary is on the machine (or `ANIMEOS_BLENDER_BIN` points at one), each render job spawns a fresh worker: `blender -b -P bridges/blender/animeos_bridge.py -- --worker --job <file>`. Since v4.0 the worker renders the DESIGNED pass: AnimeOS compiles the production's design text (model-sheet anchors, appearance notes, wardrobe/weapon states, environment briefs) into design DNA (`src/lib/animation/design.ts`) and sends it with every job, so the worker builds the DESIGNED character (stylized smooth figure, layered robes with sleeves, cuffs, sash and skirt panels, hairstyle per DNA - topknot / ponytail / braid / long / short, per-DNA weapon - sword / staff / spear - with the character's energy color, high collar, glowing stylized eyes) on a DESIGNED set (terrain per environment - terrace / peak / forest / gorge / temple - plus features: two moons, pagoda silhouette, bronze bell, wind banners, pillar stubs, bamboo, sea of clouds, lanterns, waterfall and stream, with a time-of-day sky and key light; a second detected character blocks across the set). A prop-scale camera table frames the 0.9m figure properly (chest/face-height targets, 1.9x distances). Without DNA the worker falls back to the v3.3 stand-in figure and set. It builds the set and drives a camera rig through the shot's movement grammar frame by frame, applies the AnimeOS scene parameters, renders with Cycles CPU and encodes h264 (system ffmpeg, or Blender's own FFMPEG writer). Shots carrying a pose program get an **articulated stand-in figure** whose joints interpolate between the start/end poses with eased timing - lunges, casts, walk cycles with stride swing and root bob - and the rig follows the subject's travel so the body stays framed. The v3.2 rig adds a **face and hands**: emissive eyes that squint and blink on a deterministic schedule, brows that knit angry or lift surprised, a mouth that opens with effort, and on each arm a palm, four fingers and a thumb that curl into grips, spread to channel energy or extend an index to point - every pose carries a 7-channel face/hand row eased between the endpoints exactly like the joints, and tight shot types aim the camera at the head so closeups frame the performance. The v3.3 rig makes the face **speak**: a shot with SPEECH dialogue and a tight framing arrives with a millisecond viseme program and the mouth performs the lines frame by frame - vowels open, m/b/p press shut, "ee" spreads, "oo" purses, and the pose's effort mouth stays as the floor. The program is **audio-driven over the real TTS take**: the take's WAV is analyzed frame by frame (RMS energy opens the mouth, zero-crossing rate separates voiced vowels from wide fricative hisses, silence closes), so the lips match the audio the viewer hears; the v3.4 program adds the **neural viseme pass**: an LLM plans the dialogue's phoneme-level mouth shapes (a 15-entry vocabulary - round oo, wide ee, lips-shut stops - weights clamped, cached per line set) and the plan's identity is CONFORMED onto the audio envelope, which keeps ownership of openness and timing, so consonants land where the words put them; without a take the plan performs the line itself, and a refused model degrades to the audio-only then text pass without blocking the render. One 3D worker at a time; overflow jobs fall to the MOTION engine.
- **MOTION engine (built-in).** A deterministic camera program (per-movement zoom/pan/tilt profiles x shot-type framing x lens character x lighting grade x fog/lightning/energy) is animated over the shot's key art with ffmpeg zoompan - or over a procedural gradient plate when no art exists - and encoded at the project's fps. Pose pairs play here as a blocking approximation: the program notes them and lands an impact beat at the end pose. Speaking closeups get a blocking speech beat per spoken line (a soft shimmer over each line's window) so the cut still reads as "someone is talking here".
- **img2vid previz slot (opt-in, default off).** Demoted: the studio's output is designed, not generated, so the interpolation model is previz and benchmark only. When explicitly enabled (`ANIMEOS_IMG2VID=on|zai|previz`) or a host is attached, pose-carrying hero shots route to it: the shot's key art (inlined as a data URL) plus a pose/camera program go to the async video-generation API; on a speaking closeup the prompt also carries the lines as explicit speech direction; the finished animatic downloads back into `public/renders/` and plays in the same queue behind a PREVIZ chip. An attached host wins (`ANIMEOS_IMG2VID_HOST` speaking the tiny jobs protocol); unset flag and no host means the slot is invisible and the designed engines (Blender, MOTION) take every job. A provider lost mid-job degrades to the MOTION engine transparently (and rebuilds the speech program so the takeover keeps the lip-sync).
- **Native Blender runtime + asset library (v4.1).** The studio owns its Blender: `src/lib/blender/runtime.ts` detects the binary, auto-provisions the pinned release (download.blender.org) when a workspace reset wipes it, starts a RESIDENT headless bridge on :8101 that it health-probes and restarts with backoff (the per-job spawn path stays as fallback), and exposes an exec sandbox (`blender_exec`) where the DSH designer runs real bpy passes. The design-time library (`src/lib/blender/assets.ts` + `bridges/blender/asset_builder.py`): one design DNA in, one versioned .blend + a lit 512px Cycles preview out (`assets/blender/`, previews served from `/assets-blender/`), a `BlenderAsset` row per character/environment carrying version, build log, DNA audit and an honest vision identity score vs the canonical sheet. READY assets ride every render payload; the worker appends the .blend and resolves the SAME v3.x/v4.0 rig contract by base object name, so poses, lip-sync and camera math are untouched - a missing file falls back to the procedural DNA builders honestly, and the worker state reports `figureSource` / `setSource` so every job's asset decision is auditable.
- **Workstation attach.** Run the bridge server inside any Blender (GUI or headless) and point `ANIMEOS_BLENDER_HOST` at it: jobs go over HTTP and the finished clip returns as base64.

```bash
# inside any Blender ≥ 3.x (GUI or headless):
blender -b -P bridges/blender/animeos_bridge.py -- --port 8100
# then point the studio at it and restart the dev server:
ANIMEOS_BLENDER_HOST=127.0.0.1:8100 bun run dev
```

The add-on exposes `GET /status`, `GET /progress`, `POST /render`, `POST /ping` on `127.0.0.1`. Every engine maps the tunable scene parameters (fog, lightning, energy, rim light, camera distance) onto its own equivalents, honors the shot grammar (ESTABLISHING→24mm wide … EXTREME_CLOSEUP→100mm), streams per-frame progress into the same queue UI, and lands an mp4 in `public/renders/`. If an attached bridge drops mid-job the driver chain takes over transparently.

### Try the loop

1. Open **Render Queue**, trigger a render on any shot - the **Engine driver** card shows whether headless Blender workers or the built-in MOTION engine is driving; the job badge shows `BLENDER`, `PREVIZ` (the opt-in previz slot) or `MOTION`. Give the shot a **pose program** first (panel inspector > Motion poses, or DSH `set_shot_poses`) and the clip shows the character performing: the Blender stand-in lunges, casts or walks between the start and end poses. Or skip the authoring: hit the panel inspector's **Use state poses** and the featured character's episode-active state lands its preset (a furious state performs STANCE → LUNGE).
2. Same view, pick an episode in **Episode cut** and hit *Export cut (mp4)*: the episode's clips concatenate in story order, the stems synthesize server-side (real TTS takes included) and video + audio mux into one downloadable cut with its manifest. Then pick the episode in **Publishing** and hit *Stage package*: the cut is conformance-checked against the platform preset (try Douyin with a 16:9 cut for the honest FAIL), and the package carries the title/description/tags, the SRT subtitle sidecar and the upload checklist.
3. Watch the evaluation come back `NEEDS_REVISION` with bounded parameter fixes → **Apply fixes** auto-queues attempt 2.
4. Open **DSH Director** and talk to the studio: *"For scene 12 shot 3: author the dialogue, generate a model sheet for any new character, then paint the panel in manhua style"* - the 56-tool trace shows the director doing it itself. Ask it to *"shift to a cold moonlit silver-blue palette"* and it retunes the production's style direction itself. Ask it to *"land the beat breakdown for episode 1"* and a per-episode template lands as a proposal in the plans panel. Ask *"how is the studio doing?"* and `studio_pulse` answers with the canon score, identity standing, drift curves, schedule outcomes and queue pressure. Ask *"catch me up"* and `post_digest` lands a digest of the last 24 hours in the studio digest panel.
5. Open **Characters** - hit ✦ on a character to generate their **model sheet**; the stored anchor then steers every panel they appear in (cards show an `ANCHOR` badge once locked).
6. Open **Comic Mode** and flip the same episode between manhua / webtoon / manga layouts. Bubbles (speech / thought / SFX) place themselves around the art - mirrored for manga RTL - **Print / PDF** exports pages with chrome hidden, and in webtoon format **Export slices** downloads a ZIP of 800px platform-ready strips whose audio stems mix real TTS voice takes into the score.
7. In **Comic Mode**, open **Motion sound** on a motion panel: auto-score the timeline, hit **Render voices** to give every dialogue cue a real TTS take performed by the speaker's cast artist in the speaker's current character state (or pick a voice, speed and an explicit excited / injured delivery per cue, plus a directorial note), and preview - exported stems use the same takes. Author **line-level delivery** in the dialogue editor (the ✎ on any panel) to play one shot's lines in mixed registers; the motion-sound board shows which line direction outranks the standing one.
8. Open **Artists** to run **voice casting**: give each roster artist a TTS voice, then bind characters to the artist who speaks for them. **Audition** any voice first - the board renders a throwaway sample (your line, or the character's own first line, in a chosen register) without saving a take - or pick a development state under a character and hear exactly how that state performs (variant voice + speed/pitch hints). Every proposed read lands in the state's **audition history** (replayable, removable), and **any two recorded reads chain back to back**: pick sides A and B, hit *compare A · B*, and hear them one after the other. Select several characters for an **ensemble try** and DSH or the board renders an A/B row per speaker with a sequence play. Ask DSH to do the same with `cast_voice_actor`, and to set standing deliveries scene-wide with `direct_voice_takes`.
9. After a state beat or a line edit, open **Direction diff** in the Comic Mode toolbar: every take is compared against today's direction and **Re-render affected** touches only the stale ones (fresh takes are never re-rendered).
10. Open **LoRA** and hit **Train all** to batch-fine-tune every idle adapter from the approved panels (each run shows a live loss curve), or **Train** a single one; then open **Workload** and hit **Distribute pool (affinity-first)** to route unassigned panels to the artist whose style affinity is highest for each panel's adapter.
11. Back in **Render Queue**, use **Batch render**: tick two episodes, hit *Queue N renders*, and watch the queue fill, DSH inspect each preview (throttled per poll), and the stats row track active / review / approved. Finished cards carry the **per-provider readout** ("MOTION 12.4s (built-in ffmpeg)", ~credits when a hosted provider billed) and the **provider ledger** aggregates latency and cost per engine above the queue.
12. Open **Continuity** and scroll to **Identity similarity**: after panel art exists for sheeted characters, *Score worst 3* vision-scores the panels against every featured character's model sheet - rows show per-character percentages, anything below the 60% identity bar lands in the re-paint queue with a one-click *Re-paint + re-score*, and the *Affinity pass* button embeds every panel and sheet locally (block-robust region hashes + palette histograms, instant and provider-free) to keep a drift tripwire alive when the vision provider is down. When a character's drift curve DECLINES because the design itself moved, press **Re-anchor** on their curve row: the canonical sheet regenerates, an IDENTITY_REANCHOR event marks the baseline restart (the dashed violet marker on the sparkline), and their recent panels re-score against the new sheet. Just below, **Canon health** rolls the universe-facts verdict history into a score with per-fact status rows. In **DSH Director**, the plans panel's **Per-episode templates** section lands a shaped plan (beat breakdown, panel pass, render pass, canon audit) for the picked episode - approve it, run it by hand, or arm a nightly schedule and the studio breaks the episode down while you sleep - and asking DSH for a `studio_pulse` reads the whole studio's health (canon score, identity and affinity, 14-day schedule outcomes, queue pressure) in one instant line.

## Roadmap - what is not achieved yet, and how we will get there

The plan's destination is an AI-native studio that takes a story from prose to published, animated episodes with zero manual coordination. The thesis loop is closed, but these parts of the vision are still open:

1. **Performance-grade character motion.** Characters move inside the frame: shots carry start/end pose chips (13-pose vocabulary), every development state carries a **pose preset** (auto-resolved from the label, steerable per state, landable on shots in one click), the Blender worker articulates a stand-in between the poses with a **full face and hand rig** (blinking emissive eyes, tilting brows, an effort mouth, and fingers that grip the blade, spread to channel or extend to point, with blade follow-through), the **img2vid previz slot is DEMOTED to opt-in previz** (default-off: the output is designed, not AI-generated; `ANIMEOS_IMG2VID=on` or an attached host previews a pose beat as an animatic behind a PREVIZ chip, never as the deliverable), the MOTION engine plays an impact-beat approximation, and **speaking closeups lip-sync**: the mouth rig performs a viseme program **derived from the real TTS take's audio** (RMS energy opens the mouth, zero-crossing rate separates voiced vowels from wide fricatives, silence closes; the dialogue-text program remains the fallback when a take is missing), the img2vid prompt gets the lines as speech direction, and MOTION lands a blocking speech beat. The **neural viseme pass** landed: an LLM plans the dialogue's phoneme-level viseme score (a 15-entry mouth-shape vocabulary, weights clamped, cached per line set) and the audio path CONFORMS to it - openness stays audio-owned while wide/round identity and closed-stop placement come from the plan; without a take the plan performs the line itself (a strict upgrade over the per-character table), and a refused model degrades to the audio-only then text pass without blocking the render. And the **acoustic-model slot landed**: the take is segmented deterministically into speech runs, real silences and syllable anchors, the plan's units re-time over the real speech (a unit a pause interrupts continues after it, boundaries snap to acoustic valleys, coverage stops where the voice stopped), so the mouth shapes land where the VOICE put the words - `ANIMEOS_ACOUSTIC=off` keeps the plan's even spread. What is still missing: physics-accurate interaction with props and cloth, learned interpolation quality on par with the best closed video models, and timestamped phoneme alignment (the neural rung hears WORDS through ASR; it does not yet place phonemes to the millisecond).
2. **Continuity checking that sees the universe, not just the sheet.** The art layer joined the continuity engine: a deterministic scan flags stale art (panel predates the episode-active state or the current model-sheet anchor) and missing anchors, a **VLM deep check** compares a hero panel against the character's canonical model sheet (ART_DRIFT / ART_VERIFIED events), and **universe-facts vision checks** judge every panel against the production's canon rules with a confidence per fact - confident violations rank into a worst-first re-render queue. The loop now CLOSES ITSELF: every panel prompt carries the production's active canon (**fact-aware art prompts**), the **supervised auto re-paint runner** walks the queue worst-first without the clicks - each step re-paints with the flagged facts restated as corrections, re-checks with the vision model, records FIXED / STILL_BROKEN / ERROR, and still-broken panels stop retrying and wait for the director (pause / resume / abort between steps, run state persisted and streamed to the Continuity view) - panels carry an **identity score**: one vision call scores the panel against EVERY featured character's model sheet (0..1 per character plus face/hair/wardrobe/weapon/palette/style aspects), persists per shot, and a worst below the 60% identity bar queues the panel for a one-click re-paint + re-score (IDENTITY_VERIFIED / IDENTITY_DRIFT events, DSH `score_panel_identity` targeted, worst-first batch or default-to-worst) - and the whole history reads back as a HEALTH READOUT: the **canon health** panel rolls the fact verdict history into a 0..1 score (0.4 coverage + 0.6 hold rate over active facts, an unchecked canon is not a healthy canon) with per-fact status rows (HELD / VIOLATED / UNVERIFIED, worst-first) - and the panel now SUGGESTS ITS OWN FIX: a fact audited on 3+ panels whose hold rate fell under a third earns an **auto-retire suggestion** (worst first, the reason names the counts and the reword-or-retire fork), with Reword (PATCH the text in place) and Retire (deactivate) buttons in the canon-health panel and the suggestion riding `studio_pulse` and the DSH context. The curves went FACT-LEVEL: every verdict becomes a point on a per-fact confidence curve over episode order (same trend bands as the character curves, steepest decline first), DECLINING facts surface in the canon-health panel with inline sparklines, `studio_pulse` and the DSH context name them - a fact losing verdict confidence across the show is headed for a violation streak, and the reword-or-retire suggestion is the exit - and the **reworded-fact re-audit helper** closed the loop: rewording a fact (Reword button, or the canon-health API) automatically re-runs the vision check on every panel that audited the OLD wording, so those same panels answer whether the NEW wording holds, the fresh verdicts feed the health score and the drift curves, art-less targets are reported as honestly skipped, and everything lands as a CONTINUITY event - and the suggestions are CURVE-AWARE now: a fact whose confidence curve DECLINES steadily across episodes earns the reword-or-retire suggestion even while its hold rate is still perfect, so the writing fix lands one episode earlier. The reword loop went SELF-SERVE: a reword records the OLD wording on the fact (`lastRewordedFrom`), and the **reword drift sweep** (canon-health panel button, `reaudit-drifted` action) re-audits every pending fact in one capped pass - a fact closes when its panels were actually re-checked under the new wording, or vacuously when nothing ever audited the old wording (a marker that could never serve would never clear). Next: a reword-aware curve break marker.
3. **DSH across turns and days.** The director used to reason only inside one 4-round turn. Now work that will not fit lands as a **cross-turn plan**: create_plan writes an ordered tool-call list (each step with a why, capped at 12) that starts PROPOSED in the creator's **plan review panel** on the DSH view; approving opens the runner and run_plan executes the next 1-3 steps per call through the real tool path (a failed step parks the plan AT that step for a retry), with pause/resume/abort steering and every result recorded on the plan plus production events - and the plan's progress rides the production context, so a LATER conversation picks it up exactly where it stopped. The studio now also RUNS ON A CADENCE: `create_schedule` arms recurring work (a PLAN_RUN walks an approved plan maxSteps per fire, so nightly breakdowns execute themselves once the plan is approved; a REPAINT_QUEUE watch ticks active render jobs and starts a supervised re-paint pass when the universe-facts queue is dirty and no run is live), an in-process minute loop fires due schedules between conversations, each fire claims its slot first (no double-runs) and lands a production event with its outcome (OK / SKIPPED with the reason / ERROR) on the row for the creator to audit, and DSH steers schedules with `create_schedule` / `steer_schedule`. The nightly-breakdown pattern now has a ONE-CLICK entry: the plans panel carries **per-episode plan templates** (beat-breakdown opens a fresh scene with a three-shot cinematography breakdown, panel-pass paints and scans a scene's first three panels, render-pass queues previews plus a direction diff, canon-audit vision-verdicts the hero panel against the facts); landing one resolves the episode's real scene/shot numbers into a PROPOSED plan the creator approves once and runs by hand or arms on a nightly schedule (UI, DSH `land_episode_plan`) - and the creator can now author VARIATIONS: the plans panel's author clones a built-in's resolved steps, reshapes every row (tool, args JSON, why), saves it to the production or the studio library with `{episode}`/`{latestScene}`/`{title}` tokens that resolve per episode at landing, and lands it by name or id exactly like a built-in (tools validated against the registry on save and again at landing, usage-counted). And every engine now reports **per-provider latency and estimated cost**: each render job records a telemetry span per provider that worked on it (takeover chains preserved), hosted providers bill documented per-clip-second credits while local compute bills zero, the queue card reads the chain back ("MOTION 12.4s (built-in ffmpeg)"), and a provider ledger aggregates jobs, average/total latency and credits per engine. The cadence also reports its health now: a **schedule-health digest** aggregates the 14-day fire history per schedule (OK / skipped / error counts, consecutive-error streaks, OVERDUE flags for armed schedules whose next fire slipped) into chips on the scheduler panel, a line in the DSH context and a `studio_pulse` segment. And the studio WRITES TO THE CREATOR: a **DAILY_DIGEST schedule** posts a digest of the last 24 hours (renders queued, plan steps executed, schedule fires with error counts, canon and identity-drift headlines, queue pressure) as a DIGEST production event the studio digest panel shows with its full section lines and history, `post_digest` lands one on demand, and the digest panel has a one-click Arm nightly digest shortcut. And the digest DELIVERS ITSELF BEYOND THE STUDIO now: a DAILY_DIGEST schedule carries `webhookUrl` / `digestEmail` targets (validated at registration, steerable any time via the digest panel's Delivery editor or a PATCH), every fire POSTs the digest JSON to the webhook and mails it via SMTP when `ANIMEOS_SMTP_URL` is configured, and every delivery outcome - OK or the honest FAILED, including "no SMTP transport configured" - is recorded on the digest event and rendered as chips on the digest cards. And the delivery spine grew a LAST MILE: `publish_cut` stages platform publish packages (YOUTUBE, BILIBILI, DOUYIN, TIKTOK, STUDIO_INGEST) - the episode's latest cut is probed and conformance-checked against the preset (duration cap, canvas/aspect - a 16:9 cut honestly FAILS a 9:16 platform, file size, frame rate, bitrate), the package carries clamped metadata, a provenance credits line and an SRT built from the episode's dialogue timed through the cut manifest, and the integration status is honest (credentials present, or a manual hand-off checklist) - NO network upload ever happens silently; packages land as PUBLISH events the render view's publishing panel lists, each staging now WRITES its hand-off folder to disk (`public/renders/cuts/packages/EP01/<platform>/`: package.json + the SRT + checklist.txt - the folder is what gets zipped for ingest or dragged onto an upload form), and the cadence scheduler gained a **PUBLISH_RUN** kind: a schedule pins an episode + platform and stages its package on a cadence (conformance checks and hand-off folder included, next fire computed, every outcome a production event). What is still missing: per-variation schedule presets and richer webhook templates; the adapters speak the platforms' documented upload flows and read credentials from the environment, so real-account OAuth walks are the remaining step.
4. **Voice scale and character voices.** TTS is a fixed catalog of voices with rate-limit ceilings (the E2E suite backs off on 429s), and voices are cast, not cloned - UNTIL NOW for the clone half: the **voice-clone slot** landed (`train_voice_clone`, the characters view's Train-voice button): a character's rendered takes (up to 6 of their real performed audio) go to the configured cloning provider (`ANIMEOS_VOICE_CLONE_URL`), the trained voice id persists on the character, and their lines perform with THEIR voice through the provider - a state voice variant still deliberately overrides, the catalog voice is the honest clone-fallback (stamped as such in the take's signature so diffs stay truthful), and every refusal (no provider, no takes, provider error) is reported instead of pretending. What is still missing: a provider abstraction with retry/backoff plus render caching keyed on voice + text + delivery + speed/pitch, and rate-limit headroom for the catalog.
5. **Evaluation that measures consistency.** Render evaluation is LLM-graded on composition, the vision-model identity score puts a number on each panel's resemblance to its cast's anchors, and a **provider-free embedding distance** now runs underneath it: every panel and sheet is embedded locally (a 64-bit dHash for structure plus a 4x4x4 palette histogram, through sharp, zero providers), compared by cosine + hamming into an affinity per character, persisted per shot and surfaced as chips on the identity rows, a rider on every DSH identity score, an instant *Affinity pass* button and a watch line when the vision provider is rate-limited (the tripwire honestly never replaces the vision verdict). **Per-character drift curves** now join the affinity history: every identity score becomes a point on a character's curve over episode order (story-ordered points, delta and trend band at 5 points - DECLINING / IMPROVING / STABLE / FLAT), the weakest aspect across the curve is named, declining characters surface as a watch in `studio_pulse` and the DSH context, and the identity panel draws each curve as an inline sparkline so a slide across the SHOW is visible at a glance. And identity scoring now looks at the SHIPPING PIXELS: every finished render clip donates a poster frame (ffmpeg, 40% into the clip, cached per job), and the same vision verdict path scores it against the cast's sheets as a separate RENDER-source row beside the PANEL score (drift curves stay panel-canonical so a shot does not double-count) - the storyboard passing while the render drifts is now a number the studio can see. What is still missing: a render path that carries the designed identity faithfully enough to clear the 60% bar (the v4.0 designed render pass - robes, hair, weapon and set compiled from the same design text the sheets were painted from - closes most of the stand-in gap; the stylized-procedural figure still scores low against painted sheets, honestly). The **design-time asset library** attacks the same gap from the other side: characters and environments are DESIGNED once into versioned .blend assets (with an asset-level vision score: build, inspect, refine, re-inspect - the design loop raised the cast's asset identity before a single render was spent) and every render loads the asset. The tripwire is now COMPOSITION-ROBUST: every panel and sheet carries, beside the global 64-bit dHash, a 3x3 grid of per-region 16-bit dHashes and 2x2 quadrant palette histograms; blocks whose neighbour-difference signal is below the flat gate abstain, the survivors vote and the vote pools by MEDIAN, so a reframe (a crop-shift, a subject that drifts a block over) holds at 100% block agreement where the global hash drops to 78% - proven in `scripts/check-block-affinity.ts` - while a real grade drift still reads clearly lower than a faithful panel. And the identity loop CLOSES ITSELF now: the **re-anchor workflow** (identity panel button, `reanchor_character`) regenerates a DECLINING character's canonical sheet from their CURRENT design text, lands an IDENTITY_REANCHOR event that restarts the curve's trend baseline (a dashed violet marker on the sparkline; old points stay as history), and re-scores their recent panels against the new sheet in the same call - re-paints fix panels, re-anchor fixes the reference, and doctrine rule 21 teaches DSH the difference.
6. **A studio with more than one person in it.** The FIRST HALF LANDED: the studio has a door - multi-user auth with role-gated writes (bcrypt accounts, first registration becomes OWNER, VIEWER read-only enforced by the Next 16 proxy on every mutating API call, EDITOR directs and edits, OWNER manages the roster from the header's Studio roster panel with last-OWNER protection, and sensitive routes re-read the role fresh from the DB so changes land immediately). What is still missing: per-role VIEW emphasis (director / artist / voice actor see different dashboards), comment threads anchored to panels and takes, an approval gate that feeds the same render pipeline, and per-project membership scoping (the workspace is shared - every member sees every production - rather than siloed).
7. **Distribution beyond the file.** Webtoon slices, page BOOKS (server-assembled **CBZ** with ComicInfo.xml carrying the manga RTL binding, and **PDF** with panels composed at their real grid placements and a ViewerPreferences Direction hint for right-to-left reading), print PDFs and episode cuts download locally, subtitles translate through the Terminology memory into any language (glossary-enforced, suggestions grow the memory), and the delivery spine STAGES platform publish packages (conformance checks, clamped metadata, SRT sidecars) and now UPLOADS them: `upload_package` runs each platform's real adapter (YOUTUBE resumable init+PUT, TIKTOK/DOUYIN init-then-put, BILIBILI multipart submit) when the environment carries the credential, with every outcome recorded on the package's PUBLISH event. Next: a release calendar and real-account OAuth walks.

Each item lands the same way the last twelve iterations did: one thin, testable slice at a time, every step verified against the production database and the running studio.
