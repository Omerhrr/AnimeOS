# AI-Native Animation Production Platform

> **An AI-native production system for creating, managing, and operating complete animated productions using DSH, Blender, and open-source infrastructure.**

---

# 1. Vision

Build a production platform where a creator can describe an animated production in natural language and **DSH orchestrates the entire production pipeline**.

The platform should support:

* Donghua
* Anime
* Korean / manhwa-inspired animation
* General animation
* 3D animation
* 2D animation
* Hybrid 2D/3D animation
* Feature films
* Series
* Short films
* Episodic productions
* Multilingual subtitles
* Optional dubbing

The system should not merely generate isolated images or clips.

It should maintain a **persistent animated universe** containing:

* Characters
* Character development
* Character variants
* Clones
* Avatars
* Transformations
* Reincarnations
* Possession states
* Environments
* Props
* Creatures
* Abilities
* Animation libraries
* Scenes
* Shots
* Story state
* Continuity
* Audio
* Localization
* Rendering
* Production history

The central idea:

> **DSH is the brain. Blender is the production engine. The platform is the production environment.**

---

# 2. Core Thesis

This is not an "AI image generator."

It is not simply:

```text
Prompt
  ↓
AI
  ↓
Video
```

Instead:

```text
Creative Intent
      ↓
     DSH
      ↓
Planning
      ↓
Production Tools
      ↓
Asset / Scene Construction
      ↓
Blender
      ↓
Animation / Lighting / VFX / Rendering
      ↓
Inspection
      ↓
DSH Evaluation
      ↓
Revision
      ↓
Approved Production
```

The system should behave more like an **AI-native animation studio**.

# 5. DSH: The Brain

DSH is responsible for:

* Understanding user intent
* Planning production tasks
* Calling tools
* Maintaining context
* Maintaining production state
* Maintaining character state
* Maintaining story state
* Detecting missing assets
* Detecting continuity conflicts
* Coordinating Blender
* Coordinating media tools
* Evaluating previews
* Deciding when to retry
* Deciding when to modify
* Deciding when a shot is complete
* Managing long-running production workflows

The core loop is:

```text
INTENT
  ↓
PLAN
  ↓
EXECUTE
  ↓
OBSERVE
  ↓
EVALUATE
  ↓
MODIFY
  ↓
EXECUTE
  ↓
APPROVE
```

# 6. DSH Should Not Directly Write Random Blender Scripts

Avoid making the architecture:

```text
User
 ↓
LLM
 ↓
Huge Blender Python script
 ↓
Blender
```

Instead:

```text
User
 ↓
DSH
 ↓
Domain Tool
 ↓
Production API
 ↓
Blender Bridge
 ↓
Blender Python API
```

DSH operates at a high production level.

For example:

```text
character.create()
scene.create()
character.add_to_scene()
camera.create()
lighting.create()
animation.apply()
vfx.create()
render.preview()
render.final()
```

The Blender bridge handles the actual `bpy` operations.

This creates a stable abstraction layer between DSH and Blender.

# 19. Character State Types

DSH must distinguish:

## Permanent Development

Example:

```text
Lin Yue loses his left arm.
```

This changes his canonical state from that point onward.

## Temporary Scene State

Example:

```text
Lin Yue is covered in blood.
```

This applies to the scene but does not permanently alter the character.

## Variant

Example:

```text
Lin Yue wears formal robes.
```

This is an appearance variant.

# 21. Clones

If Lin Yue creates 1,000 clones, the system should not create 1,000 completely independent assets.

Instead:

```text
Lin Yue
   │
   └── Clone Technique
         │
         ├── Clone 001
         ├── Clone 002
         ├── Clone 003
         └── ...
```

They can share:

* Model
* Rig
* Materials
* Animation library
* Base clothing

while having unique:

* Position
* State
* Equipment
* Damage
* Abilities
* Temporary effects

This dramatically reduces production overhead.

# 26. Missing Capability Detection

When DSH receives a scene requirement, it should compare the story requirement against the current production state.

Example:

```text
SCENE REQUIREMENTS

Character:
    Lin Yue ✓

Environment:
    Battlefield ✓

Weapon:
    Jade Sword ✓

Combat Animation:
    ✓

Azure Flame:
    ✗

Azure Flame VFX:
    ✗
```

DSH then determines what must be created.

```text
create_ability()
create_animation()
create_vfx()
```

This is how the system can intelligently expand a character over time.

---

# 27. Continuity Engine

Continuity is a first-class system.

Example:

```text
Episode 29:
Jade Sword destroyed.
```

Episode 32:

```text
Script:
Lin Yue draws Jade Sword.
```

DSH should detect:

```text
CONTINUITY CONFLICT

Required:
Jade Sword

Canonical history:
Jade Sword destroyed in Episode 29.

Possible resolutions:
1. Script error
2. Flashback
3. Sword restored
4. Alternate weapon
```

The system should not silently create an inconsistent asset.

```text

 ↓
```

```text
 ↓
Inspect
 ↓

 ↓

 ↓

 ↓
```

```text
- Increase sword energy emission.
```

Then DSH calls the appropriate tools.

# 68. Core Architecture Principle

The most important architectural rule is:

```text
                         DSH
                          │
                   Makes decisions
                          │
                          ▼
                    TOOL INTERFACE
                          │
             ┌────────────┼────────────┐
             ▼            ▼            ▼
         Production     Blender       Media
             │            │            │
             └────────────┼────────────┘
                          ▼
                       OUTPUT
                          │
                          ▼
                     DSH REVIEW
                          │
                          └──────→ ITERATE
```

DSH should know **what needs to happen**.

The production tools know **how to perform it**.

Blender knows **how to construct and render the 3D world**.

FFmpeg and the media systems know **how to assemble the final production**.
